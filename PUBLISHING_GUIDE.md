# Ward Shabdam - Production Publishing & Deployment Guide

This guide covers everything required to deploy the **Flask Web/API Backend** and publish the **Flutter Android Application** to Google Play.

---

## 1. Project Architecture Overview

The system consists of two tightly integrated components:

1. **Flask Web & API Backend** (`app.py`, `database/`, `templates/`, `static/`):
   - Public Civic Portal: Announcements, Programs, Circulars, Downloads, Gallery, Surveys.
   - Citizen Portal: Registration, login, complaint submission, tracking, notifications, profile.
   - Admin Dashboard: Complaint management, analytics, PDF report generation, citizen management.
   - Ward Member Portal: Ward-specific dashboards, member notes, reminders.
   - REST API: Endpoints under `/api/*` consumed by the Flutter mobile application.
   - Deployment Target: **Render** (or any Docker/VPS container with Gunicorn).

2. **Flutter Mobile Application** (`ward_shabdam_app/`):
   - Package / Namespace: `com.wardshabdam.app`
   - Target Platforms: Android (Google Play Store / APK / AAB)
   - Connects to the backend via `API_BASE_URL` compile-time environment definition.

## 2. Backend Deployment (Render / Cloud)

### Prerequisites
- A GitHub repository containing the latest code.
- A free or paid account on [Render.com](https://render.com).
- A Gmail account with an **App Password** (for automated citizen notification emails).

### Step 1: Prepare Environment Variables
Refer to `.env.example`. When configuring the service on Render:

| Variable | Description | Example / Recommended Value |
|---|---|---|
| `WARD_SHABDAM_SECRET_KEY` | Flask session key | Auto-generated by Render |
| `FLASK_DEBUG` | Debug mode toggle | `0` (Production) |
| `WARD_SHABDAM_ADMIN_USERNAME` | Default master admin username | `admin` |
| `WARD_SHABDAM_ADMIN_PASSWORD` | Default master admin password | Set a strong password |
| `WARD_SHABDAM_MAIL_SERVER` | SMTP host | `smtp.gmail.com` |
| `WARD_SHABDAM_MAIL_PORT` | SMTP port | `587` |
| `WARD_SHABDAM_MAIL_USE_TLS` | TLS encryption flag | `1` |
| `WARD_SHABDAM_MAIL_USERNAME` | Sending email | `your-panchayat@gmail.com` |
| `WARD_SHABDAM_MAIL_PASSWORD` | 16-character App Password | `xxxx xxxx xxxx xxxx` |
| `WARD_SHABDAM_ADMIN_EMAIL` | Alerts destination email | `admin@your-panchayat.gov` |
| `WARD_SHABDAM_DB_PATH` | *(Optional)* Persistent DB path | `/var/data/wardshabdam.db` (if persistent disk attached) |

> [!NOTE]
> On Render's free tier, the filesystem is ephemeral (resets on redeploy). The app automatically creates all tables and an initial administrator account on startup. For permanent storage on Render, attach a **Persistent Disk** (under Disks tab) mounted at `/var/data` and set `WARD_SHABDAM_DB_PATH=/var/data/wardshabdam.db`.

### Step 2: Deploy to Render via Blueprint or Web Service
1. Connect your GitHub repository to Render.
2. If using **Blueprint**: Render will automatically detect `render.yaml` and configure the web service.
3. If creating a **Web Service** manually:
   - **Environment**: Python
   - **Build Command**: `pip install -r requirements.txt && python create_db.py`
   - **Start Command**: `gunicorn app:app`
   - **Health Check Path**: `/`
4. Deploy the service. Note the assigned public domain (e.g., `https://wardshabdam.onrender.com`).

## 3. Flutter Android App Publishing (Google Play Store)

### Step 1: Release Signing Configuration
The Android release configuration in `ward_shabdam_app/android/app/build.gradle.kts` uses `key.properties`.

Ensure `ward_shabdam_app/android/key.properties` exists locally:
```properties
storeFile=release-keystore.jks
storePassword=thachanattukara@2026
keyAlias=wardhabdam
keyPassword=thachanattukara@2026
```
> [!CAUTION]
> Never commit `release-keystore.jks` or `key.properties` to version control. They are strictly protected in `.gitignore`. Keep a secure offline backup of your `.jks` file; losing it means you cannot update your app on Google Play!

### Step 2: Build the Google Play App Bundle (.aab)
Google Play requires an **Android App Bundle (`.aab`)** for store submission:

```powershell
cd ward_shabdam_app
flutter build appbundle --release --dart-define=API_BASE_URL=https://your-production-domain.com
```

Output location:
`ward_shabdam_app/build/app/outputs/bundle/release/app-release.aab`

### Step 3: Build a Direct Standalone APK (for testing or sideloading)
```powershell
cd ward_shabdam_app
flutter build apk --release --dart-define=API_BASE_URL=https://your-production-domain.com
```

Output location:
`ward_shabdam_app/build/app/outputs/flutter-apk/app-release.apk`

## 4. Google Play Console Checklist

Before uploading `app-release.aab` to Google Play Console:

1. **App Identity**:
   - Package Name: `com.wardshabdam.app`
   - Version: configured in `ward_shabdam_app/pubspec.yaml` (e.g., `version: 1.0.0+1`). Increment both for every subsequent release.
2. **App Details**:
   - Title: **Ward Shabdam** (or Ward Voice)
   - Short description (up to 80 chars)
   - Full description (describing ward services, announcements, complaint submission, tracking)
3. **Graphics Assets**:
   - App Icon: 512x512 PNG (`ward_shabdam_app/assets/logo.png`)
   - Feature Graphic: 1024x500 PNG
   - Phone Screenshots: At least 2 phone screenshots (e.g., Home screen, Complaint screen)
4. **Data Safety & Permissions**:
   - Permissions used: `android.permission.INTERNET` (Network communication).
   - Data collection: Citizen Name, Mobile, Email, and Complaints (User feedback/civic reports).
5. **Privacy Policy**:
   - Provide a valid HTTPS privacy policy URL hosted on your web domain (e.g., `https://your-domain.com/privacy`).
